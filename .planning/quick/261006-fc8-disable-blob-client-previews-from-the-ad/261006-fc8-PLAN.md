Planner decisions (documented here, not scope additions):
- The marker body is the string `disabled`, not `''`. The orchestrator's draft used an empty body, but `put()` rejects falsy bodies (see interfaces). The index only looks at the pathname, so the content does not matter. The README asks for "a small file with any content".
- The marker's uploadedAt does NOT bump updatedAt. "Atualizado em" keeps meaning "last content change", and disabling does not move the preview to the top of the newest-first list. A folder whose only blob is the marker falls back to the marker's uploadedAt, so updatedAt is always a valid ISO string (formatDateTime would throw on an empty one).
- Only `.disabled` directly under the slug folder is the marker. `<slug>/img/.disabled` is an ordinary file.
- Disable does not touch the global `client-previews` CDN tag. Other sites' assets must not go stale. The disabled site's asset entries are deleted through `client-preview:<slug>`, and `updateTag` expires both the index and the `/preview/<slug>` ISR page. Enable needs no CDN call: while disabled, every response was a no-store 404, and the site's CDN entries were deleted on disable.
- Disable order is put, then updateTag, then dangerouslyDeleteByTag. If writing the marker fails, nothing else happens and the action throws, so the site never ends up with its CDN copies gone while the index still says it is enabled. A unit test covers this.
- `allowOverwrite: true` makes "Desativar prévia" idempotent. Clicking it again rewrites the marker and deletes the CDN entries again, which is the fix if a request re-cached an asset in the moment between the CDN delete and the end of the action (T-fc8-05).
- In servePreviewAsset the index read comes after `isSafePreviewPath`, so unsafe paths still cost no Blob or index call.
- "Limpar cache deste site" is hidden while a preview is disabled, because 404s are no-store and nothing is cached. "Abrir" stays, so Luiz can confirm the 404.
- The toggle is shown only for Blob rows. Repo previews come back through a commit, and the README says so.
- The Blob-only admin UI cannot render with real data locally (no credentials, and none may be created). Task 3 renders it once from a temporary, uncommitted fixture in the index's catch branch, takes 375 px screenshots, then restores the file. It never clicks an action button.
