Planner decisions (documented here, not scope additions):
- The form field is named `confirmation`. It is compared with `!==` against the slug, with no trim or case folding, so "acme " and "Acme" delete nothing.
- The batch size is 100 pathnames per del() call. The API documents no limit, and small requests keep one bad batch from failing a large one.
- The action lists everything first, then deletes. A listing failure therefore deletes nothing. A failed batch stops the loop, and the retry lists whatever is left. Each del() call gets pathnames, not URLs, the same as enablePreview.
- On failure the redirect goes to `/admin/<slug>?delete=failed`, the page that holds the retry form. If the store is completely unreachable, the rebuilt index is unavailable and that page answers 404 like any admin page whose preview is not indexed. The dashboard then shows the existing "Blob indisponível" alert, and the retry works once Blob is back. The README says so in one clause.
- `dangerouslyDeleteByTag` runs on both paths, after the deletes. Its errors are not caught, the same as in disablePreview, and outside Vercel it does nothing. Running it after the deletes means a request in between can only re-cache a file that still exists.
- No logging in the catch, since `src/` has no console calls. The failure is visible through the alert.
- The input gets `required`, `pattern={preview.slug}`, `autoCapitalize="none"`, `autoCorrect="off"`, `spellCheck={false}` and `autoComplete="off"`. The browser refuses a mismatched slug before any request is sent, and iOS cannot turn the first letter into a capital. The server check stays the authority. Slugs are `[a-z0-9-]`, so the slug is a literal pattern.
- The block renders only when `preview.source === 'blob' && isPreviewSlug(preview.slug)`. The action ignores any other slug, and such folders already carry the invalid-slug warning.
- On success the preview drops out of the dashboard. No extra success banner (not requested).
- Blob previews cannot render in e2e (CI has no credentials), so no e2e test is added. The UI is checked once from a temporary, uncommitted fixture stub (Task 2).
