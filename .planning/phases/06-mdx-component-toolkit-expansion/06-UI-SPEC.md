## Spacing Scale

Declared values (multiples of 4, inherited from project — no phase-specific exceptions):

| Token | Value | Usage in Phase 6 components |
|-------|-------|------------------------------|
| xs | 4px | — |
| sm | 8px | `gap-2` in CodeFilename filename bar (icon-to-text gap) |
| md | 16px | `px-4` CodeFilename filename bar horizontal padding |
| lg | 24px | `my-6` on Callout/Stat patterns (inherited) |
| xl | 32px | — |
| 2xl | 48px | — |
| 3xl | 64px | — |

**Phase 6 specific spacing:**

| Component | Property | Value | Tailwind class |
|-----------|----------|-------|----------------|
| CodeFilename filename bar | padding | 8px top/bottom, 16px left/right | `py-2 px-4` |
| CodeFilename filename bar | icon gap | 8px | `gap-2` |
| CodeFilename FileIcon | size | 14px × 14px | `size-3.5` |
| InlineBadge | horizontal padding | 8px | `px-2` |
| InlineBadge | vertical padding | 2px | `py-0.5` |
| InlineBadge | border-radius | full | `rounded-full` |

Exceptions:

| Value | Tailwind | Justification |
|-------|----------|---------------|
| 14px (`size-3.5`) | FileIcon width/height | Standard Lucide icon sizing at `text-xs` scale — 14px is proportional to the 12px label text; `size-3` (12px) is too small and `size-4` (16px) adds visual imbalance. Matches established Lucide usage in `callout.tsx` (`size-4` at `text-sm` scale, adjusted down for the `text-xs` filename bar). |
| 2px (`py-0.5`) | InlineBadge vertical chip padding | Required to render inline without breaking prose line-height. `py-1` (4px, 8px total) adds too much height to a `text-xs` chip and disrupts surrounding body text flow. 2px is the standard micro-padding for inline chips at this scale. |

## Component Visual Specifications

### CodeFilename — full visual anatomy

```
┌─────────────────────────────────────────────────────┐  ← rounded-md border border-border
│  [FileIcon 14px, aria-hidden]  src/app/page.tsx      │  ← bg-muted/50, py-2 px-4, border-b border-border
│  text-xs font-mono text-muted-foreground, gap-2      │
├─────────────────────────────────────────────────────┤
│                                                      │
│  [PreWithCopyButton renders here — children passthru]│  ← existing pre: override fires naturally
│                                                      │
└─────────────────────────────────────────────────────┘
  overflow-hidden clips inner pre to outer border-radius
```

**Authoring shape in MDX:**
```mdx
<CodeFilename filename="src/app/page.tsx">
```tsx
export default function Page() { ... }
```
</CodeFilename>
```

**aria-label:** `"{ariaPrefix}: {filename}"` — EN: `"File: src/app/page.tsx"`, PT: `"Arquivo: src/app/page.tsx"`.

**Mobile constraint (iPhone SE 375px):** `overflow-hidden` on the outer container clips the border-radius only. The `[data-rehype-pretty-code-figure] pre { overflow-x: auto }` rule in `globals.css` (line 123) must remain honored. If `overflow-hidden` clips horizontal scroll, executor must replace with `overflow-x-clip` or apply `rounded-md` without `overflow-hidden` and handle radius clipping via children. Verify on 375px viewport before marking done. (RESEARCH Pitfall 2)

### InlineBadge — full visual anatomy

```
 inline text ‣ [primary label]  inline text ‣ [destructive label]  ‣ inline text
                ↑
                rounded-full border px-2 py-0.5 text-xs font-medium
                does NOT break prose line-height
                <span> not <div> — inline formatting context preserved
```

**Authoring shape in MDX:**
```mdx
Use <InlineBadge>primary</InlineBadge> or
<InlineBadge variant="destructive">breaking change</InlineBadge>
```

**Renders inline:** `inline-flex` keeps chip height proportional to line height. No block-level formatting context break.

## Interaction Contract

### CodeFilename
- No interactive behaviour of its own.
- Copy button interaction is owned by the inner `PreWithCopyButton` (existing client island — unchanged).
- No hover, focus, or click states on the filename bar.
- Keyboard: filename bar is not focusable (`tabIndex` not set; the containing `<div>` with `aria-label` is a landmark description, not an interactive element).

### InlineBadge
- No interactive behaviour. Static chip.
- No hover, focus, or click states.
- Not focusable. Not a button.
- Screen reader reads inline as part of surrounding prose text flow.

### Reduced motion
- Neither component has animation. The project-wide `@media (prefers-reduced-motion: reduce)` block in `globals.css` has no effect on these components. No additional handling needed.

| Requirement | CodeFilename | InlineBadge |

| Screen reader label | `aria-label` on outer `<div>` provides localized prefix + filename | renders inline in prose; no extra aria needed |

**WCAG 1.4.3 note for `muted-foreground` on `muted/50` background:**
- Jedi: `oklch(38%)` text on `oklch(90% / 50%)` background = approximately `oklch(94%)` effective. Contrast ≥ 4.5:1. (muted-foreground was explicitly darkened to 38% for this case — globals.css line 37 comment.)
- Sith: `oklch(70%)` text on `oklch(18% / 50%)` background = approximately `oklch(14%)` effective. Contrast ≥ 4.5:1. (muted-foreground was explicitly lightened to 70% — globals.css line 58 comment.)
