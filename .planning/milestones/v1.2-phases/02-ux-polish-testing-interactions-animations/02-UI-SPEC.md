## Spacing Scale

Standard 8-point scale. Pre-populated from existing sections — all are consistent.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap (`gap-1`), badge padding |
| sm | 8px | Compact element spacing, chip `px-3 py-1` |
| md | 16px | Default element spacing (`px-4`), section horizontal padding |
| lg | 24px | Inter-element gaps, `gap-6` in card grids |
| xl | 32px | Layout gaps |
| 2xl | 48px | Section vertical padding (`py-12`) |
| 3xl | 64px | Hero vertical padding on desktop (`py-20`) |

Exceptions:
- Interactive button touch targets: `h-11` (44px) on all buttons and anchor CTAs — required for WCAG 2.5.5 minimum target size. Already established across all sections; must not be reduced.
- Card image aspect ratio: `aspect-[16/10]` (not spacing, but a locked dimensional contract for all project cards).

## Typography

All values pre-populated from codebase scan. No changes in Phase 2 — this is a polish phase only.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (prose) | 16px (`text-base`) | 400 (regular) | `leading-relaxed` (~1.625) |
| Body (small / descriptions) | 14px (`text-sm`) | 400 (regular) | 1.5 (default) |
| Label (interactive / caps) | 10px (`text-[10px]`) | 400 (regular), uppercase, `tracking-wide` — Badge only; visual weight from uppercase + tracking, not from weight bump |

Exactly 4 declared sizes (10px, 14px, 16px, 24/48px). Exactly 2 declared weights: 400 (regular) for body, small body, and badge label; 600 (semibold) for all headings including the display h1. Source: `hero.tsx`, `skills.tsx`, `personal-projects.tsx`, `featured-projects-teaser.tsx`, `contact.tsx`.

## Interaction Contracts

This phase is primarily interaction polish. The following contracts are the authoritative specification for every interactive element across all in-scope homepage sections.

### Primary Button (filled)

```
bg-primary text-primary-foreground
h-11 px-6 rounded-md font-semibold
transition-opacity hover:opacity-90
focus-visible:outline-none focus-visible:ring-3 focus-visible:ring-ring/50
```

Usage: Hero Contact CTA, Contact mailto link. No changes in Phase 2.

### Secondary Button / Ghost Button (bordered)

```
border border-border
h-11 px-4 rounded-md text-sm
transition-colors hover:bg-muted
focus-visible:outline-none focus-visible:ring-3 focus-visible:ring-ring/50
```

Usage: Hero Resume CTA, Contact bordered links (LinkedIn, GitHub, Resume, CopyEmailButton). No changes in Phase 2.

### Card Hover (project cards — FeaturedProjects + PersonalProjects)

```
transition hover:-translate-y-0.5 hover:shadow-md
```

Applied at the wrapping link or Card element. This is the established pattern from `featured-projects-teaser.tsx`. Any in-scope section with card-like elements that does NOT apply this pattern is a deviation to fix during the UX-12 audit.

### Skills Badge Hover

```
transition-all hover:border-primary/50 hover:shadow-sm
```

Skills items use a lighter treatment than project cards (shadow-sm not shadow-md; no translate). This is intentional and must not be harmonized to the card pattern.

### Filter Chip (Skills — active and inactive)

```
/* Inactive */
border-border bg-background text-muted-foreground
hover:border-primary hover:text-primary

/* Active */
border-primary bg-primary text-primary-foreground
```

No changes in Phase 2.

### Inline Link Hover (FeaturedProjects section nav, PersonalProjects card links)

```
/* Primary (nav-style) links */
text-foreground underline decoration-primary decoration-2 underline-offset-4
hover:decoration-foreground

/* Secondary (muted) links */
text-muted-foreground underline-offset-4
hover:text-foreground hover:underline
```

Any in-scope interactive link that deviates from these two patterns is a UX-12 audit fix target.

### Focus Ring (global)

```css
/* globals.css — already declared */
*:focus-visible {
  outline: 2px solid var(--ring);
  outline-offset: 2px;
}
```

Per-component override (Shadcn components): `focus-visible:outline-none focus-visible:ring-3 focus-visible:ring-ring/50`

The global CSS rule and the per-component class are the same visual output. Both must remain in place. Any interactive element that uses only `focus-visible:outline-none` without the `ring-3` classes is a UX-12 audit fix target.

## Animation Contract

### Scroll-Reveal Entry (RevealGroup + RevealItem)

Canonical implementation: `src/components/ui/reveal-group.tsx`.

| Property | Value | Source |
|----------|-------|--------|
| Entry motion | `opacity: 0, y: 16` → `opacity: 1, y: 0` | `childVariant` in `reveal-group.tsx` |
| Duration | 400ms | `childVariant.show.transition.duration` |
| Easing | `easeOut` | `childVariant.show.transition.ease` |
| Viewport trigger margin | `−60px` | `RevealGroup` `viewport.margin` |
| Trigger once | Yes | `viewport.once: true` |
| Stagger — Skills | `0.04s` | Section-appropriate (many small items) |
| Stagger — PersonalProjects | `0.07s` | Already in place; UX-11 verified |
| Stagger — FeaturedProjects | `0.08s` | Established reference |
| Stagger — Career | `0.08s` | Established reference |
| Stagger — Contact | `0.05s` | Small number of items |

Stagger values are intentionally section-appropriate. Do NOT harmonize to a single value.

### CopyEmailButton Icon Swap Animation (UX-09 — new in Phase 2)

```
/* AnimatePresence + motion.span, or useReducedMotion + conditional opacity */
Initial (entering Check icon): { opacity: 0, scale: 0.6 }
Animate: { opacity: 1, scale: 1 }
Exit (leaving CopyIcon): { opacity: 0, scale: 0.6 }
Duration: 150ms
Easing: match existing easeOut curve
```

Implementation approach is at Claude's discretion (CONTEXT.md): `AnimatePresence` + key-based swap OR `useReducedMotion` inline guard. Either is acceptable; choose whichever produces cleaner code.

Reduced motion behavior: instant swap — no opacity or scale transition. The global `prefers-reduced-motion` CSS rule in `globals.css` covers CSS transitions; the motion JS animation must also check `useReducedMotion()` or be wrapped in `<MotionConfig reducedMotion="user">`.

### Screenshot Hover Zoom (PersonalProjects — existing)

```
transition-transform duration-500 group-hover:scale-105
```

Applied to `<Image>` inside `ProjectScreenshot`. Already implemented; no changes. Verify this still works after screenshots are added for the 4 gradient-placeholder projects.

### Reduced Motion Global Contract

```css
/* globals.css — already declared */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation: none !important;
    transition: none !important;
    scroll-behavior: auto !important;
  }
}
```

This overrides ALL CSS transitions and animations site-wide. The `motion@^12.38` JS animations additionally require `useReducedMotion()` or `<MotionConfig reducedMotion="user">` because Motion runs outside the CSS cascade.
